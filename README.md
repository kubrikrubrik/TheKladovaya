# Кладовая — домашний учёт продуктов, покупки и рецепты

Сайт для повседневного использования: учёт всего, что есть дома, автоматический список покупок, база товаров и библиотека из 1026 рецептов с подбором по имеющимся продуктам. Работает без сервера — на GitHub Pages или любом статическом хостинге. Интерфейс на русском языке.

---

## Что внутри

Все файлы лежат в одной папке, вложенных папок нет.

## Загрузка на GitHub через веб-интерфейс

1. Войдите на [github.com](https://github.com) и нажмите **New repository** (зелёная кнопка или «+» в правом верхнем углу).
2. Название — например, `kladovaya`. Выберите **Public** (для бесплатного GitHub Pages репозиторий должен быть публичным, если у вас не платный тариф). Нажмите **Create repository**.
3. На странице пустого репозитория нажмите ссылку **uploading an existing file**.
4. Распакуйте ZIP-архив на компьютере, выделите **все файлы** (не папку, а именно файлы) и перетащите их в окно браузера.
5. Дождитесь загрузки (файл `recipes.json` весит около 1,5 МБ — это нормально), внизу нажмите **Commit changes**.

## Публикация через GitHub Pages

1. В репозитории откройте **Settings → Pages**.
2. В блоке **Build and deployment** выберите **Source: Deploy from a branch**.
3. **Branch:** `main`, папка **/(root)**. Нажмите **Save**.
4. Через 1–3 минуты вверху страницы появится адрес вида `https://ваш-логин.github.io/kladovaya/`. Откройте его.

Все пути в проекте относительные, поэтому сайт работает и в подпапке репозитория, и в корне домена.

**Обновление сайта.** Загрузите изменённые файлы тем же способом (**Add file → Upload files**) — одноимённые файлы заменятся. Пользовательские данные при этом не пострадают: они хранятся в браузере, а не на GitHub. Новая версия подхватывается при следующем открытии (иногда со второго раза — так работает офлайн-кэш).

**Локальная проверка без GitHub.** Двойной щелчок по `index.html` не сработает: браузеры запрещают загружать JSON-базы с диска. Запустите в папке проекта `python -m http.server 8000` и откройте `http://localhost:8000`.

**Установка на телефон.** Откройте сайт в Chrome (Android) или Safari (iPhone) и выберите «Добавить на главный экран». Приложение откроется без адресной строки и будет работать без интернета.

## Как пользоваться

### Мои продукты
- **Быстрое добавление.** Наберите в верхней строке «молоко 2 шт», «гречка увелка», «сыр 300 г» или «яйца 10». Первая подсказка покажет, как система поняла ввод (название, количество, категория), — Enter добавляет. Ниже — товары из базы с фасовками: нажмите на фасовку, и товар добавится с брендом, категорией, весом и количеством единиц в упаковке.
- **Через поиск** — кнопка «Добавить продукт» или «+» в нижнем меню телефона: найдите товар, выберите фасовку, укажите число упаковок и минимальный остаток.
- **Вручную** — если товара нет в базе: название, категория, единица учёта, единиц в упаковке, вес или объём, количество, минимальный и желаемый запас.
- **Два уровня учёта.** Количество хранится во внутренних единицах (пакетики, штуки, бутылки, граммы). Пример: 3 упаковки гречки по 5 пакетиков = 15 пакетиков; «Съели» спишет один пакетик — останется 14 («2 упаковки по 5 и ещё 4 пакетика, всего 1,12 кг»).
- **Кнопки в строке:** «−»/«+» исправляют количество, «Съели» списывает одну единицу и учитывает её в расходе (из этого строится прогноз покупок). Меню «⋯»: добавить или списать целую упаковку, списать часть (в граммах, единицах или упаковках), «Закончилось», в список покупок, удалить. Почти всё можно отменить кнопкой «Отменить» во всплывающем уведомлении.
- **Статусы:** «Достаточно», «Заканчивается» (остаток равен минимальному или меньше), «Закончилось». Шкала под названием — уровень запаса, риска на ней — минимальный остаток.
- **Категории** — кнопка «Категории»: создание, переименование, перестановка, удаление (продукты удалённой категории переезжают в «Прочее»).

### Список покупок
- Пополняется сам: как только продукт доходит до минимума или заканчивается, он появляется в списке с рекомендуемым количеством. Если задан «Желаемый запас», рекомендация доводит до него, иначе — до минимального остатка; для упаковок число округляется вверх до целых упаковок.
- Количество можно менять, переключать между упаковками и штуками, удалять позиции, добавлять товары вручную, объединять одинаковые, сортировать и скрывать купленные.
- **«Куплено»** (кружок слева) сразу добавляет покупку в запасы — к существующему продукту, без дублей. Повторное нажатие отменяет покупку и возвращает остаток.
- **«Покупки на эту неделю»:** закончилось, скоро закончится, желательно докупить (прогноз по вашему расходу за последние недели — появляется, когда наберётся история) и общее число позиций. «Обновить список» пересобирает рекомендации по текущим остаткам.

### Рецепты
- Наверху всегда видно, что можно приготовить прямо сейчас и где не хватает одного продукта. Во всей библиотеке блюда, которые можно приготовить полностью, стоят выше остальных при любой сортировке.
- Фильтры: 18 разделов, время, сложность, калорийность порции, тип блюда, основной ингредиент, «только из имеющихся».
- На странице рецепта у каждого ингредиента видно: есть дома (и какой именно продукт), не хватает по количеству (сколько докупить), нет дома. Кнопки «В список покупок» и «Добавить недостающее» работают одним нажатием. Число порций можно менять — количества пересчитываются.
- **«Я приготовил это блюдо»** показывает предварительный список списания: какой продукт, сколько спишется и сколько останется. Ничего не списывается до подтверждения; лишние строки можно снять. После подтверждения пересчитываются остатки, список покупок и доступность других рецептов.
- **Свой рецепт** — кнопка «Свой рецепт»: ингредиенты пишутся по строкам («Творог 500 г», «Соль по вкусу»), система сразу показывает, какие связались с запасами.
- Сопоставление учитывает синонимы (картошка = картофель, томат = помидор, филе курицы = куриное филе) и иерархию (куриное филе подходит туда, где нужна «курица»), но не допускает ложных замен: томатная паста не считается свежими помидорами, плавленый сыр — твёрдым. Вода, соль и чёрный перец считаются всегда имеющимися (список меняется в настройках).

### База продуктов
- Поиск по части названия, бренду, с исправлением опечаток («гречкп» → гречка) и неправильной раскладки («uhtxrf» → гречка); латинские бренды находятся и по-русски («макфа» → Makfa).
- Фильтры по категории, магазину и источнику. Нажатие на фасовку — добавить в запасы, в список покупок или сделать свою копию записи.
- Свои товары: «Новый товар», импорт CSV или JSON (кнопка «Шаблон CSV» скачает пример с колонками `name;brand;category;key;unit;perPack;size;measure;stores;barcode`), выгрузка своих записей.
- **Open Food Facts** — открытая база товаров со штрихкодами: поиск по названию, по штрихкоду и сканирование камерой (в браузерах с поддержкой BarcodeDetector, например Chrome на Android). Нужен интернет; найденный товар сохраняется в ваши записи.

## Честно о базе продуктов

Прямого открытого доступа к каталогам Самоката, Пятёрочки, Перекрёстка, Чижика, Ашана, Ленты, Магнита, ВкусВилла, METRO и О'КЕЙ нет, поэтому справочная база собрана так, чтобы ничего не выдумывать:

- **Типовые товары (702)** — без бренда, в распространённых фасовках: «Молоко 3,2%, 1 л», «Яйцо куриное С1, 10 шт», «Гречка развесная».
- **Брендовые товары (417)** — известные марки (Увелка, Мистраль, Makfa, Barilla, Простоквашино, Coca-Cola, Добрый и другие). Фасовка указана только там, где она общеизвестна; если нет уверенности — поле оставлено пустым, и вы укажете его при добавлении.
- **Собственные марки сетей (51)** — только те, принадлежность которых известна точно (например, «Красная цена» — Пятёрочка, «Каждый день» — Ашан, «365 дней» — Лента, Aro и Horeca Select — METRO, ВкусВилл). Наличие национальных брендов в конкретном магазине база не гарантирует.
- **Штрихкоды в справочной базе не указаны**, чтобы не выдавать непроверенные коды за настоящие. Реальные штрихкоды появляются у товаров из Open Food Facts и у тех, что вы добавили сами.
- Справочные записи и ваши записи хранятся раздельно и помечены в интерфейсе («Типовой товар», «Бренд», «Собственная марка», «Моя запись», «Импорт», «Open Food Facts»).

**Как обновлять базу.** Отредактируйте `products.json` (массив `items`, поля описаны ниже) и загрузите на GitHub, затем в разделе «База продуктов» нажмите «Обновить базу». Либо импортируйте CSV/JSON прямо в приложении — такие записи сохранятся в браузере.

```json
{ "id": "p0001", "name": "Гречка ядрица", "brand": "Увелка", "category": "grains", "key": "гречка",
  "unit": "пакетик", "perPack": 5, "size": 80, "measure": "г", "stores": ["Пятёрочка"], "barcode": "…", "source": "brand" }
```
`unit` — внутренняя единица учёта; `perPack` — сколько их в упаковке; `size` и `measure` — вес или объём одной единицы; для весовых товаров `unit` = `г`; `key` — ингредиент из `ingredients.json`, по нему товар участвует в подборе рецептов.

## О рецептах и изображениях

В библиотеке 1026 разных блюд: супы, салаты, горячее из курицы, мяса и рыбы, паста, гарниры, выпечка, десерты, закуски, завтраки, напитки, соусы и заготовки. 763 рецепта написаны каждый по отдельности; остальные 263 — группы по одной технологии (супы-пюре, омлеты, каши, котлеты, пицца, пирожки, вареники, смузи и т. п.), где у каждого блюда свой набор ингредиентов, пропорции и свои шаги. Калорийность на порцию рассчитана по ингредиентам и помечена «≈».

**Фотографий блюд в комплекте нет.** Подобрать 1026 разных фотографий, каждая из которых точно соответствует блюду, без водяных знаков и с правом на использование, автоматически невозможно, а повторяющиеся или случайные снимки ТЗ запрещает. Вместо них у каждого рецепта аккуратная обложка: цвет по типу блюда и крупная буквица. Чтобы добавить фото, положите файл (например, `borsch.jpg`) в корень репозитория и пропишите у рецепта в `recipes.json` поле `"image": "borsch.jpg"` — или укажите ссылку в поле «Фото блюда» у своего рецепта. Если файл не загрузится, снова покажется обложка, битых картинок не будет.

Формат рецепта в `recipes.json`:
```json
{ "id": "r0001", "title": "Борщ", "type": "Суп", "categories": ["Супы", "Обеды"], "time": 150, "difficulty": 2,
  "servings": 6, "kcal": 345, "description": "…",
  "ingredients": [{ "name": "Свёкла", "key": "свёкла", "qty": 2, "unit": "шт" }, { "name": "Соль", "key": "соль", "optional": true }],
  "steps": ["…", "…"] }
```
Единицы: `г`, `кг`, `мл`, `л`, `шт`, `ст.л.`, `ч.л.`, `стакан`, `зуб` (зубчик), `пучок`, `щепотка`, `банка`, `упаковка`. В `key` можно указать массив допустимых замен: `["спагетти", "макароны"]`.

## Резервное копирование и восстановление

Данные хранятся только в браузере на этом устройстве (IndexedDB). Они переживают перезагрузку страницы и перезапуск браузера, но пропадут, если очистить данные сайта или пользоваться режимом инкогнито.

**Сделать копию:** «Настройки и копии» (шестерёнка вверху на телефоне, пункт внизу меню на компьютере) → **Скачать резервную копию**. Сохранится файл `kladovaya-backup-ГГГГ-ММ-ДД.json` со всем сразу: продуктами, остатками, категориями, списком покупок, своими рецептами и товарами, историей расхода и настройками. В меню видно, когда была последняя копия, и появится напоминание, если прошло больше двух недель.

**Восстановить:** там же → **Восстановить из файла** → выберите JSON → «Заменить текущие данные копией» (полная замена) или «Объединить с текущими данными» (добавит недостающее, ничего не удалит).

**Перенести на другое устройство:** скачайте копию на первом устройстве (можно сохранить в облако или отправить себе), откройте сайт на втором и восстановите из файла.

## Синхронизация между устройствами

Сейчас синхронизации нет: на телефоне и на ноутбуке будут независимые данные. Это ограничение сайта без сервера. Реалистичные пути добавить её позже:

1. **Без программирования — через файл.** Хранить резервную копию в облаке (Яндекс Диск, Google Drive) и восстанавливать на другом устройстве. Подходит, если основное устройство одно.
2. **Облачная база с входом по почте — рекомендуемый путь.** Подключить бесплатный тариф Supabase или Firebase. Вся работа с хранилищем сосредоточена в `storage.js` (методы `get`/`set` для коллекций `inventory`, `shopping`, `categories`, `customRecipes`, `userProducts`, `settings`, `history`), поэтому достаточно дописать отправку изменений в облако и загрузку при входе. Каждая запись уже имеет уникальный `id` и время изменения `updatedAt`, так что при конфликте побеждает более свежая версия, а данные остаются доступными офлайн. Сайт по-прежнему остаётся на GitHub Pages — сервер не нужен.
3. **Свой маленький сервер.** Cloudflare Workers с хранилищем KV или D1: одна функция принимает и отдаёт JSON по секретному ключу семьи. Чуть больше настройки, полный контроль над данными.

## Тестирование перед выпуском

Проект проверен автотестами в браузере Chrome (Playwright) на сайте, размещённом в подпапке, как на GitHub Pages. Пройдены все 18 сценариев из технического задания и дополнительные проверки (31 проверка, 0 ошибок):

добавление через поиск; ручное добавление; товар с внутренними единицами (3 упаковки по 5 пакетиков = 15); списание одной единицы (15 → 14 пакетиков); списание целой упаковки; изменение количества; запрет отрицательного остатка; удаление с отменой; создание категории; изменение минимального остатка и смена статуса; автоматическое появление в списке покупок; отметка «Куплено»; добавление покупки в запасы без дублей и отмена покупки; объединение одинаковых позиций; поиск рецептов по категории и по продукту; подбор по запасам и сортировка «готовые выше»; определение недостающих ингредиентов; списание после приготовления с предварительным списком; сохранение после перезагрузки; экспорт и импорт копии; поиск по базе с опечатками, раскладкой и частью названия.

Мобильная версия и разные экраны (375, 390, 768, 1360, 1440 и 1920 пикселей): нет горизонтальной прокрутки, элементы не выходят за край экрана, ошибок JavaScript нет.

Что не удалось проверить в тестовой среде без интернета: загрузку шрифтов Google Fonts (Literata и Onest — без сети используются системные шрифты) и запросы к Open Food Facts. Эти функции рассчитаны на работу онлайн и при недоступности сети показывают понятное сообщение.
